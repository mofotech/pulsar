Pulsar is a lightweight IaaS orchestration platform built as a single Go binary. It runs as either a controller (control plane: REST API + gRPC) or an agent (data plane: compute, network, or storage pillar). State is split between etcd (live cluster state) and PostgreSQL (identity, quotas, audit). Networking is powered by OVN/OVS with VXLAN/VLAN overlays; compute is driven by libvirt/KVM.

🔐

Identity

Mostly Complete
  • JWT-based auth (login → token; includes jti, org_id, org_role claims)
  • Password hashing (bcrypt; legacy dev-nohash rows still accepted)
  • Token revocation — JTI deny-list in etcd with TTL; checked on every authenticated request
  • Multi-tenancy via projects
  • Role-based access (admin / member) — enforced on all identity mutation endpoints
  • User CRUD (create, list, update role/password)
  • Project CRUD (create, list, rename, delete — admin only)
  • SSH keypairs (generate RSA-4096 or import; injected via cloud-init)
  • Organizations (multi-tenant; platform_admin-managed; default pulsar org)
  • OpenID Connect / SSO — per-org IDP config; OIDC authorize + callback; auto-provisioning; federated_identities link table
  • IDP discovery endpoint — GET /v1/auth/idps?email=… for email-to-IDP resolution (domain_hint)
  • Personal access tokens (PATs) — pat_-prefix opaque tokens; bcrypt-hashed; expiry; last_used_at tracking
  • PAT auth in middleware — dual JWT/PAT path in AuthMiddleware; compatible with all API routes
  • pulsarctl login sso — browser OIDC flow with ephemeral loopback callback server
  • pulsarctl login token — store PAT as active credentials
  • Project scope middleware — validates project membership + org boundary per request
  • Fine-grained RBAC — admin/member enforced; no per-resource ownership checks yet
